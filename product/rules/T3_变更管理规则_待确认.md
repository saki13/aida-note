# T3 变更管理规则

> 版本：v0.1.0
> 资产归类：产品资产 -> 治理规则
> 对应 Backlog：`T3`（变更管理能力）
> 作用：定义 AidaPulse 项目中变更的识别、评估、批准、同步和追溯机制，确保变更可执行、可追查、可追溯。
> 上级文档：[AidaPulse 白皮书 v0.1.0](../whitepaper/AidaPulse白皮书_待确认.md)
> 关联规则：AS-Panel 看板数据源同步规则、AS-SIS Backlog↔SIS 转化规则、G3 未决议题池管理规则、G5 流程守门与阻断机制
> 演进：AS-Panel 是本规则的前置聚焦案例（data.json 同步），本规则将其泛化为通用派生资产同步机制。

---

## 1. 变更定义

**变更 = Aida 正常工作范围外，对范围内文档的更改。**

### 1.1 什么是变更

| 场景 | 是否变更 | 说明 |
|------|---------|------|
| 甲方要求调整 PCB 文档 | ✅ 变更 | 外部因素导致项目纲领修改 |
| 资源不足，SIS 无法执行，需降级需求，改 SIS + Backlog | ✅ 变更 | 执行受阻导致需求降级 |
| PO 调整需求方向，新增/删除/修改 Backlog 项 | ✅ 变更 | 需求层面的变更 |
| 技术方案调整，需修改已确定的设计决策 | ✅ 变更 | 设计决策层面的变更 |
| Aida 执行 SIS 后更新 state.md / manifest.md | ❌ 不是变更 | Aida 正常工作范围内的状态维护 |
| Aida 标记 context_cache stale 并刷新 | ❌ 不是变更 | 记忆系统自主维护 |
| Aida 更新 data.json 同步看板状态 | ❌ 不是变更 | 派生资产自主同步 |
| Aida 在 decisions.md 追加执行决策 | ❌ 不是变更 | 正常决策记录 |

### 1.2 核心原则

- **记忆系统不涉及变更**：Aida 自主维护记忆和文档状态是正常工作，不走变更流程
- **变更针对的是项目交付资产**（Backlog/SIS/PCB/Sprint 文档）和 Aida 本体资产（仅本工程内）

---

## 2. 两个世界：变更边界

| 世界 | 范围 | 变更权限 |
|------|------|---------|
| **Aida 本体世界**（产品资产） | SKILL / Rules / AS 系列 / 模板 / 白皮书 | **仅在本工程内可变更**。Aida 被带到外部项目时，这些文件为只读，不可修改 |
| **项目交付世界**（建设资产） | Backlog / SIS / PCB / Sprint 文档 / 看板 | Aida 可按变更规则正常维护 |

> 类比 Scrum：Scrum Master 不会在项目过程中修改 Scrum Guide。Aida 在外部项目中也不会修改自己的 SKILL/Rules。

---

## 3. 变更分类

| 类型 | 触发场景 | 处理时机 | 谁决策 |
|------|---------|---------|--------|
| **需求变更** | PO 调整需求方向、新增/删除/修改 Backlog 项；甲方要求调整 PCB | Sprint 中允许（比 Scrum 更敏捷） | PO |
| **设计决策变更** | 技术方案调整、架构决策变更、规则修改 | 当前 Sprint 结束后讨论（除非紧急） | PO + Aida 讨论 |
| **紧急变更** | 生产缺陷、阻塞性问题、SIS 执行卡点需降级 | 立即 | PO 拍板（低风险时 Aida 可批准，见第 6 节） |

---

## 4. 变更发起权限

| 角色 | 发起权限 | 限制条件 |
|------|---------|---------|
| **PO** | 可随时提出变更 | 无限制 |
| **Agent**（非 Aida） | 仅在推进遇到**卡点**时可提出 | 必须同时触发**异步广播事件 + 变更提交** |
| **Aida** | **不允许提出变更** | 暂时限制，方便管理。后续视情况放开 |

> Aida 虽然不能提出变更，但负责执行变更的全流程（评估、同步、记录、追溯）。

---

## 5. 风险评估

所有变更必须由 Aida 进行风险评估。

### 5.1 风险等级

| 等级 | 判定标准（满足任一即升级） |
|------|------------------------|
| **低** | 影响范围 ≤3 个文件；不影响 Sprint 目标；目标偏离值 ≤20%；不涉及 PCB/白皮书 |
| **中** | 影响 4-10 个文件；影响 Sprint 目标但可调整；目标偏离值 20%-50%；涉及 Backlog 优先级调整 |
| **高** | 影响 >10 个文件；严重影响 Sprint 目标；目标偏离值 >50%；涉及 PCB/白皮书/SKILL/Rules |

### 5.2 评估产出

Aida 输出风险评估表：

```
变更 ID：change-XXX
风险等级：低/中/高
影响范围：[文件清单]
目标偏离值：X%
Sprint 目标影响：是/否
建议处理方式：立即执行 / 下次 Planning / Sprint 后讨论
```

---

## 6. 批准权限

| 风险等级 | 批准权限 | 附加条件 |
|---------|---------|---------|
| **低** | 短 Sprint 中，**Aida 可批准** | 影响范围不大 + 目标偏离值 ≤20%；批准后必须**异步广播通知 PO** + **及时修改相关文档** |
| **低**（长 Sprint） | **PO 决定** | 长 Sprint 中低风险变更也需 PO 批准 |
| **中** | **PO 决定** | Aida 给出评估建议，PO 拍板 |
| **高** | **PO 决定** | Aida 给出评估建议，PO 拍板 |

> 短 Sprint 的定义以 [AS-8](../skills/AS-8_短Sprint授权模式执行边界_待确认.md) 为准：Aida 获 PO 授权后自主走 3+4+5+6+7+8 完整 Sprint 流程（授权次数按「次短 Sprint」计）。"短"体现在时间维度而非任务数量（不限制任务数，仅要求需求高内聚），准入条件见 SKILL 第 16 节。

## 7. 变更流程

```
① 变更发起
  -> PO 提出变更 / Agent 遇卡点提出变更（同时触发异步广播 + 变更提交）
  -> Aida 记录到 change_log.md（状态：open）

② 风险评估
  -> Aida 评估风险等级、影响范围、目标偏离值
  -> 输出风险评估表
  -> 记录到 change_log.md

③ 批准决策
  -> 低风险 + 短 Sprint + 偏离 ≤20% -> Aida 可批准，异步广播 PO
  -> 其他情况 -> PO 决定是否执行
  -> 记录决策到 change_log.md + decisions.md

④ 同步执行
  -> Aida 按影响清单逐项更新（按顺序）：
     1. Backlog（主事实源）
     2. SIS（按 AS-SIS 规则）
     3. PCB（若涉及）
     4. state.md
     5. manifest.md
     6. data.json（按 AS-Panel 规则）
     7. context_cache 标记 stale
     8. decisions.md 新增条目

⑤ 追溯关闭
  -> Aida 确认所有受影响资产已同步
  -> change_log.md 状态更新为 closed
  -> 异步广播变更完成通知
```

## 8. 变更日志（change_log.md）

文件位置：`project/change_log.md`

每条变更记录包含：

| 字段 | 说明 |
|------|------|
| `change_id` | 唯一标识（change-001, change-002...） |
| `type` | 需求变更 / 设计决策变更 / 紧急变更 |
| `发起人` | PO / Agent（注明 Agent ID） |
| `发起时间` | 日期 |
| `变更内容` | 具体改了什么 |
| `变更原因` | 为什么改 |
| `风险评估` | 低/中/高 + 影响范围 + 目标偏离值 |
| `批准人` | Aida（低风险短 Sprint）/ PO |
| `批准时间` | 日期 |
| `关联 decision` | decisions.md 中的条目 ID |
| `同步状态` | syncing / completed |
| `状态` | open / approved / syncing / closed |

## 9. 同步链路（泛化 AS-Panel）

AS-Panel 定义了 data.json 的同步机制，本规则将其泛化为**通用派生资产同步链路**：

```
主事实源变更（Backlog / PCB / 决策）
  -> 一级派生资产同步：SIS / state.md / manifest.md
  -> 二级派生资产同步：data.json / context_cache
  -> 变更日志记录：change_log.md
```

**同步纪律**（硬性）：
- 先主事实源，后派生资产
- 每次同步必须更新对应时间戳
- context_cache 对应条目标记 stale
- 变更日志必须在同步完成后追加

---

## 10. 追查与追溯

| 维度 | 机制 |
|------|------|
| **追查**（从变更找资产） | change_log -> 影响范围清单 -> 逐项检查资产是否已同步 |
| **追溯**（从资产找变更） | 资产文件中的 decision 引用 -> decisions.md -> change_log |

---

## 11. 边界约束

- **Aida 本体世界变更**：仅在本工程（AidaPulse 框架建设期）允许。外部项目中 Aida 的 SKILL/Rules 为只读
- **Aida 不允许提出变更**：暂时限制，仅执行变更流程
- **不搞自动化引擎**：变更是人 + Aida 协作流程，不做文件监听/自动推送
- **记忆系统不走变更**：Aida 自主维护，不纳入变更流程

---

## 12. 与现有规则的关系

| 规则 | 关系 |
|------|------|
| AS-Panel | T3 泛化了 AS-Panel 的同步机制（data.json -> 通用派生资产） |
| AS-SIS | SIS 变更走 AS-SIS 规则，T3 负责触发 |
| G3 未决议题池 | 变更若涉及未决议题，同步更新 Backlog 中的未决状态 |
| G5 流程守门 | 变更不破坏现有阻断机制 |
| decisions.md | 变更批准必须关联一条 decision |

---

## 13. 当前不做什么

- 不做自动化的变更检测引擎
- 不做 WebSocket 实时推送
- 不允许 Aida 提出变更（暂时限制）
- 不把记忆系统维护纳入变更流程
