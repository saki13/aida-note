# G3 未决议题池管理规则（含 AS-7 持续追踪）

> 版本：v0.1.0
> 资产归类：产品资产 -> 治理规则
> 对应 Backlog：`G3`（未决议题池管理规则）+ `AS-7`（未决议题持续追踪）
> 上级文档：会议治理总规则 v0.1.0（第 6 节）
> 关联规则：AS-SIS Backlog↔SIS 转化规则、AS-Panel 看板数据源同步规则

---

## 1. 设计原则

**Backlog 就是未决议题池**。不创建独立的 `project/issues/` 文件。

- 未决议题是 Backlog 中的一条记录，不是独立实体
- 议题的"未决"状态通过 Backlog 状态字段表达
- 追踪和关闭都在 Backlog 内闭环

## 2. Backlog 条目补充字段

Backlog 标准条目包含：

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | 唯一标识 |
| `priority` | ✅ | P0/P1/P2 |
| `title` | ✅ | 议题标题 |
| `status` | ✅ | 见第 3 节状态流转 |
| `owner` | ❌ | 落实人（未决时可为空，PO 指定后填入） |
| `sis` | ❌ | SIS 引用（未决时为空，有明确行动后创建） |
| `dod` | ❌ | 验收标准（未决时为空，讨论清楚后补充） |

## 3. 未决议题生命周期

```
提出（未决）
  → Planning 中被 PO 提起
  → PO 补充 owner / dod / sis（或决定关闭/暂缓）
  → 下次讨论或执行
  → resolved（关闭或转为正式 Story）
```

**状态集合**（在 Backlog 标记中体现）：

| 状态 | Backlog 标记 | 含义 |
|------|-------------|------|
| `open` | `- [ ]` + 标注 `未决` | 已提出，等待讨论 |
| `discussion` | `- [ ]` + 标注 `讨论中` | 正在 Planning/Sync 中讨论 |
| `defined` | `- [ ]` + 补充 DoD/SIS | 已明确，等待排期执行 |
| `resolved` | `- [x]` | 已关闭（完成/放弃/合并） |

## 4. 会议中的提起规则

### 4.1 Planning 开场

Aida 必须扫描 Backlog 中所有 `未决`/`讨论中` 状态的条目，汇报给 PO：

```
Aida："以下 N 条未决议题需要讨论：
  - [id] title（当前状态：open/discussion）
```

PO 逐项决策：
- **补充**：指定 owner、补充 DoD/SIS，状态 → `defined`
- **关闭**：确认不再需要，状态 → `resolved`
- **暂缓**：保持 `open`，加注暂缓原因，下次再提
- **继续讨论**：状态 → `discussion`，下次再提

### 4.2 Review 检查

Aida 扫描所有 `discussion` 状态的条目，确认是否已有结论。如果有明确结论，更新状态。

### 4.3 Pulse Execution Sync

日常 Sync 中不主动提起未决议题（避免打断执行流）。仅在以下情况触发：
- 某个未决议题与当前执行 SIS 有直接关联
- PO 主动发起讨论

## 5. AS-7 持续追踪机制

### 5.1 追踪检查点

Aida 在以下阶段边界自动扫描 Backlog 未决状态项：

| 检查点 | 时机 | 动作 |
|--------|------|------|
| Planning 开场 | 每次 Planning 会议开始时 | 列出所有 `open`/`discussion` 条目 |
| Planning 收尾 | 启动文档产出前 | 确认本轮是否有新增未决、已有未决是否处理 |
| Review 开场 | Review 议程 4 前 | 扫描是否有长期未处理的未决议题（超 2 个 Sprint） |
| Sprint 结束 | Sprint Completed 时 | 统计：未决总数、新增数、关闭数 |

### 5.2 长期未处理告警

Aida 维护 `open` 超期判断：
- 超过 2 个 Sprint 仍在 `open` → Review 时标记为"长期未决"，提醒 PO
- 超过 3 个 Sprint → 建议 PO 明确关闭或指定 owner

## 6. 与其他规则的关系

| 规则 | 关系 |
|------|------|
| AS-SIS Backlog↔SIS 转化规则 | 未决议题 `defined` 后，按 AS-SIS 规则创建 SIS |
| AS-Panel 看板数据源同步规则 | 未决议题状态变更后，同步更新 data.json |
| 会议治理总规则第 6 节 | 本规则是第 6 节的具体执行细则，不冲突 |

## 7. 当前不做什么

- 不创建独立的 `project/issues/` 文件
- 不做自动化的议题生命周期引擎（Aida 手动扫 + PO 决策）
- 不对未决议题做复杂的依赖分析
