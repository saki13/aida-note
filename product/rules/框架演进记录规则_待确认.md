# 框架演进记录规则

> 版本：v0.1.0
> 资产归类：产品资产 -> 规则
> 对应 Backlog：`4.5` 建立框架演进记录机制
> 作用：定义 AidaPulse 框架「演进记录」的标准、字段、触发时机，让框架在项目开发过程中持续反哺自身
> 上级文档：[AidaPulse 白皮书 v0.1.0](../whitepaper/AidaPulse白皮书_待确认.md)
> 关联规则：`T3 变更管理规则`、`G3 未决议题池管理规则`

---

## 1. 定位

框架演进记录是 **AidaPulse 演进机制** 的一部分：框架在母工程（开发 Aida 本身的工程）中被使用、被检验、被改造，其中对框架有「反哺价值」的节点需要被记录，以便框架持续进化。

本规则是**产品资产**（可跨项目复用），定义「如何记录演进」；实际的记录日志是**建设资产**（项目级实例），按本规则产生，存放于 `{项目}/evolution_log.md`。

---

## 2. 记录标准

只记录「有反哺项目价值」的演进，不做流水账。以下三类值得记录：

1. **product 受限 / 问题**：product 文档（规则 / SKILL / 模板 / 白皮书）限制了项目开发，或由 product 导致的问题（最重要，属演进机制）
2. **补充机制 / 功能**：对 Aida 十分有益的补充机制和功能添加
3. **可推广 SKILL**：项目上开发、具备可推广性（可跨项目复用）的 SKILL

不符合上述三类的，不记录（即便重要，归 decisions 或 Backlog 处理）。

---

## 3. 触发时机

- **Sprint 结束（固定）**：每个 Sprint 结束时，回顾本 Sprint 是否有值得记录的演进节点
- **即时记录**：当涉及「product 文档限制项目开发」的情况时，及时记录，不等 Sprint 结束

---

## 4. 记录字段

每条记录含以下字段：

| 字段 | 说明 |
|------|------|
| 日期 | 记录时间 |
| 类型 | 里程碑 / product受限 / 补充机制 / 可推广Skill |
| 摘要 | 一句话说明演进内容 |
| 背景 | 为什么会有这次演进（触发原因、当时遇到的问题） |
| 关联 decision | 对应的 `decision-xxx`（如有） |
| 影响范围 | 影响到的 product 文档 / 能力 / 项目环节 |

类型枚举：

| 类型 | 说明 |
|------|------|
| 里程碑 | 框架的关键里程碑节点（Sprint 完成、版本升级等） |
| product受限 | product 文档限制项目开发，或由 product 导致的问题 |
| 补充机制 | 对 Aida 有益的补充机制和功能添加 |
| 可推广Skill | 项目上开发、具备可推广性的 SKILL |

---

## 5. 与 decisions.md 的分工

- `decisions.md`（L3）：决策视角的**细粒度流水**，记录所有关键决策
- `evolution_log.md`：项目视角的**粗粒度演进节点**，只记影响框架走向的节点，细节指向 `decision-xxx`

进化记录不重复 decisions 的细节，只做「索引 + 演进意义」。

---

## 6. 日志文件位置约定

- 日志实例存放于 `{项目}/evolution_log.md`（项目级，与 `change_log.md` 平行）
- 带出新项目时，仅携带本规则（产品资产），新项目按需生成自己的日志实例

---

## 7. 当前不做什么

- 不做自动化的演进检测（当前由 Aida 在 Sprint 结束 / 触发时机人工识别记录）
- 不把演进记录并入 decisions.md（保持两者分工）
- 不回溯补全历史里程碑的结构化字段（历史里程碑由项目自行决定存放位置，新记录从启用本规则起结构化）
