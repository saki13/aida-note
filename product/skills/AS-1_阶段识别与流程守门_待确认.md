# AS-1 阶段识别与流程守门规则

> 资产归类：产品资产 -> SKILL 能力规则
> 版本：v0.1.0
> 对应 Backlog：`AS-1` 阶段识别与流程守门  
> 作用：定义 Aida 在当前阶段如何识别项目所处流程阶段，并在必要时执行提醒、拦截与流程守门。
> 上级文档：[AidaPulse 白皮书 v0.1.0](../whitepaper/AidaPulse白皮书_待确认.md)

---

## 1. 能力目标

`AS-1` 的目标不是让 Aida 变成复杂流程引擎，而是先具备最基础的流程感知与守门能力：

1. 始终知道当前项目处于哪个阶段。
2. 明确当前阶段允许做什么、不应跳过什么。
3. 在发现明显跳流程、缺关键前提或不满足结束条件时进行提醒或阻断。
4. 为后续 `AS-2`、`AS-3`、`G5` 和短 Sprint 授权机制提供基础。

---

## 2. 当前阶段状态机

当前阶段，AidaPulse 会议与推进主链路采用以下状态机（与工作流图第 3 节 + 阶段流程重审表 v0.1.2 对齐）：

1. `项目准备`
2. `Backlog Grooming`
3. `Planning`
4. `Sprint In Progress`
5. `Sprint Completed`
6. `Review`
7. `Retrospective`（可选）
8. `Planning Input Ready`
9. `短 Sprint 脉冲`（可选分支）
10. `脉冲执行同步`（贯穿 Sprint）
11. `项目交付`

补充说明：

- `项目准备` 是起始阶段，PO 提供项目意图与初始资料，Aida 辅助形成初始 PCB 和 Backlog 雏形。
- `脉冲执行同步` 不是独立顺序阶段，而是贯穿 `Sprint In Progress` 的异步事件广播机制，可能在 Sprint 内多次发生。
- `Retrospective` 为可选阶段（Aida 建议 + PO 认可才开），在某些短 Sprint 场景下不是逐次触发，但若被触发且未形成结论，则把问题作为待完善项加入 Backlog，不构成阻塞节点。
- `Planning Input Ready` 是 Aida 自省阶段，不需要人类干预，只要有 Backlog 剩余项即可自动进入下一次 Planning；Backlog 燃尽则转 `项目交付`。
- `Review` 包含细分子状态：`Review Passed`、`Review Passed With Observation`、`Review Failed`。细分状态的处理方式见工作流图第 3.6 节。
- `短 Sprint 脉冲` 是可选分支：Aida 获得 PO 权限后，自主走 3+4+5+6+7+8 完整 Sprint 流程（授权次数/边界受 AS-8 约束，事件流同步 PO）。
- `项目交付` 由 `Review` 阶段检查 Backlog 池已空且 PO 决定进入交付时触发：Aida 生成项目报告并询问 PO 意见，PO 否决进新 Planning，同意则交付项目产品/项目报告/evolution_log 等项目资产。

---

## 3. 阶段识别输入

Aida 在判断当前阶段时，应优先综合以下输入：

- 当前最新会议纪要
- 当前 Sprint 启动收口文档
- 当前 Backlog 状态
- 当前是否存在进行中的 Sprint
- 最近一次 `Review / Retrospective / Planning` 结论
- 是否存在未完成的候补或阻断事项

如果上述输入之间互相冲突，Aida 不应自作主张猜测，应先提示当前阶段不确定，并要求补充确认。

## 4. 各阶段允许动作

### 4.1 项目准备

允许动作：

- 接收 PO 的项目意图与初始资料
- 辅助 PO 形成初始 `PCB` 雏形
- 辅助 PO 形成初始 `Backlog` 雏形

不应跳过：

- 初始 `PCB` 雏形
- 初始 `Backlog` 雏形

### 4.2 Backlog Grooming

允许动作：

- 收集背景材料
- 澄清项目背景与目标
- 形成初始 `PCB`
- 形成初始 `Backlog` 池
- 形成项目规范初稿
- 记录未决议题

不应跳过：

- 会前检查
- 初始 `PCB`
- 初始 `Backlog`
- 未决议题记录

### 4.3 Planning

允许动作：

- 汇报项目状态
- 更新 `Backlog`
- 选取本轮 Sprint 输入
- 识别不可进入 Sprint 的项
- 形成 Sprint 任务清单与会议纪要

不应跳过：

- 进入条件检查
- 任务池成型
- 未入选项说明
- 会议纪要

### 4.4 Sprint In Progress（含 Pulse Execution Sync）

允许动作：

- 异步状态同步
- 阻塞暴露
- 风险提示
- 资源申请
- 看板与状态更新
- 必要时发起同步小会

不应跳过：

- 状态回写
- 风险暴露
- 达到自动排障上限后的升级

### 4.5 Review

允许动作：

- 汇报交付情况
- 展示成果或验收结果
- 给出通过 / 不通过结论
- 更新 Backlog 状态
- 把未通过项重新纳入流转

不应跳过：

- 评审动作本身
- 通过 / 不通过结论
- 未通过项处理去向

### 4.6 Retrospective（可选）

> 触发条件：Aida 觉得 Sprint 中有做的不好的、需要讨论的问题，通知 PO 建议开启反思会。PO 认可后才走此流程。

允许动作：

- 复盘流程、协作、工具、质量问题
- 形成改进项
- 沉淀规则修订项
- 沉淀 Skill 候选
- 形成新增 Backlog

不应跳过：

- 形成明确结论
- 改进项记录
- 对下一轮 Planning 的治理输入

### 4.7 Planning Input Ready

允许动作：

- 从反思结论中提取候选项（如有反思纪要）
- 整理为 Planning 输入候选清单
- 检查 Backlog 是否还有剩余项
- 若 Backlog 燃尽 -> 项目交付
- 若还有剩余 -> 自动进入下一轮 Planning

不应跳过：

- Planning 输入候选清单整理
- Backlog 剩余项检查

### 4.8 短 Sprint 脉冲（可选分支）

允许动作：

- 获得 PO 授权后，自主走 3+4+5+6+7+8 完整 Sprint 流程（Planning → Sprint In Progress → Sprint Completed → Review → Retrospective → Planning Input Ready）
- 事件流同步 PO（当前记录在 data.json.events[]）

不应跳过：

- 授权次数/边界（受 AS-8 约束）
- 事件流同步 PO
- 各阶段文档/报告/数据/记忆更新

### 4.9 项目交付

允许动作：

- 生成项目报告并询问 PO 意见
- PO 否决 -> 进入新 Planning；PO 同意 -> 交付项目产品、项目报告、evolution_log 等项目资产

不应跳过：

- PO 意见确认
- 项目报告
- 交付资产齐全

## 5. 流程守门动作

### 5.1 提醒

适用于：

- 当前阶段存在轻微输入不足
- 当前阶段存在待补充信息，但尚不构成强阻断
- 当前存在未决议题，但不影响本轮主路径判断

动作表现：

- 明确提示当前阶段
- 提示缺失项
- 提示下一步应补什么

### 5.2 异议

适用于：

- 会前检查未通过
- 会议结束条件不明确满足
- 当前阶段关键资产缺失
- 当前结论不足以安全进入下一阶段

动作表现：

- 明确指出为什么不能顺滑进入下一阶段
- 说明缺失什么、需要谁补、补完后再进入什么流程

### 5.3 阻断

当前阶段与 G5 v0.1.0 对齐，采用简化阻断策略：仅 `Backlog Grooming` 设硬阻断，其余阶段不阻断。

硬阻断适用于：

- `Backlog Grooming` 缺失关键基础资产（无初始 PCB / 无初始 Backlog / 无未决议题记录）
- `Planning` 无可用任务池（PO 确认无新任务 = 项目完成；否则回到 Grooming 扩充）

以下情况不阻断，通过流程自身消化：

- `Planning` 未锁定正式输入、未产出启动文档、存在不可执行项 -> 直接继续 Planning
- `Sprint` 执行中的问题 -> 通过 Pulse Execution Sync 异步广播，由 PO 决定是否介入
- `Review` 未通过项 -> 回流到下次 Planning 或 Retrospective
- `Retrospective` 未形成结论 -> 把问题作为待完善项加入 Backlog
- 短 Sprint 准入不满足 -> 建议转常规 Sprint（非阻断，是降级）

动作表现（硬阻断时）：

- 明确说明当前阶段不能关闭
- 明确说明下一阶段不能开启
- 明确要求先回到哪个环节补齐

### 5.4 阶段切换显式申请（7.1b）

任何阶段切换前，Aida 必须：

1. 完成当前阶段的必要动作并输出收口结论
2. 显式输出「申请进入 X 阶段」并附当前阶段 DoD/收口检查结论
3. 等待 PO 明确批准
4. 仅在 PO 批准后，才修改 state / manifest / data.json 的 stage 字段

禁止：

- 自行推断「合理下一步 = 授权」
- 单次处理中连续跨越多个阶段动作（程序正义）

例外：短 Sprint 授权期间，Aida 按 AS-8 获得与 PO 相同的审批权限，可自主主持各阶段（详见 AS-8）。

## 6. 当前阶段的刚性阻断条件

当前阶段，与 G5 v0.1.0 对齐，采用简化阻断策略：仅 `Backlog Grooming` 设硬阻断，其余阶段不阻断。

1. `Backlog Grooming` 缺失关键基础资产（无初始 PCB / 无初始 Backlog / 无未决议题记录）-- 硬阻断，阻止进入 Planning
2. `Planning` 无可用任务池 -- 硬阻断（PO 确认无新任务 = 项目完成；否则回到 Grooming 扩充）

以下原列为刚性阻断的情况，现改为通过流程自身消化：

- 会前输入不足且关键材料缺失 -> 通过会前检查（AS-2）提醒补充，不阻断
- `Retrospective` 议而未决 -> 把问题作为待完善项加入 Backlog，不阻断
- 短 Sprint 任务不够明确，或缺少可自动检查的完成条件 -> 建议转常规 Sprint，非阻断

> 关于短 Sprint：短 Sprint 的"短"体现在**时间维度**上，不是限制任务数量。因为全部采用 AI 开发，Aida 可全程自主检查评估，可连续开启，执行效率高。短 Sprint 不限制任务数，只要需求高内聚即可。

---

## 7. 输出产物

当 Aida 使用 `AS-1` 时，应至少产出：

- 当前阶段判断
- 当前阶段允许动作
- 当前阶段禁止跳过的节点
- 当前是否可进入下一阶段
- 若不可进入，阻断原因与补救建议

这些输出可以存在于：

- 会前辅助包
- 会议纪要
- Sprint 启动收口
- 过程记录

---

## 8. 与其他能力的关系

- `G1` 提供会议治理总规则
- `G4` 提供 Aida 职责边界
- `AS-1` 在此基础上把"规则"变成"阶段判断 + 守门动作"
- `AS-2` 将承接 `AS-1`，把会前检查和会前辅助包做成更具体的能力定义
- `G5` 在此基础上把阻断条件写死，并提供补救路径和事件处理模板

---

## 9. 当前阶段实施原则

- 当前先追求"能判断、能提醒、能阻断"
- 暂不追求复杂自动编排
- 阶段判断如遇冲突，优先暴露不确定性，而不是强行猜测
- 流程守门的目标不是拖慢推进，而是避免错误推进
- 阻断策略与 G5 v0.1.0 对齐：仅 Backlog Grooming 硬阻断，其余通过流程消化
