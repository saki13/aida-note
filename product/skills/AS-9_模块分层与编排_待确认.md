# AS-9 Aida Skill / Agent 模块分层与编排设计

> 版本：v0.1.0
> 资产归类：产品资产 -> SKILL 能力规则
> 对应 Backlog：`AS-9` Skill / Agent 分层与编排
> 作用：定义 Aida Skill / Agent 的模块分层、上下文边界与编排关系，为 `Aida v0.1.0` 原型机提供稳定的长期架构前提，而不是临时拼装的短期骨架。
> 上级文档：[AidaPulse 白皮书 v0.1.0](../whitepaper/AidaPulse白皮书_待确认.md)

> 可视化补充：参见 [C4 架构图](../agents/aida/C4架构图_待确认.md)

---

## 1. 设计目标

`AS-9` 的目标不是直接产出一个"大而全"的 Aida，而是先回答以下问题：

1. Aida 后续应由哪些模块组成。
2. 哪些模块负责流程，哪些模块负责协议，哪些模块负责日志与审查。
3. 模块之间如何调用，哪些能力必须共享上下文，哪些能力必须隔离上下文。
4. 如何避免为了一个简单任务，把整个项目的大上下文一次性塞给 LLM。
5. 如何让 `Aida v0.1.0` 在正确架构前提下上岗，并为后续版本迭代预留空间。

---

## 2. 总体原则

### 2.1 架构正确优先于原型速度

- `Aida v0.1.0` 可以是原型机，但 `AS-9` 不能是临时拼凑的粗糙架构。
- 认知设计上应先细拆、先分层、先明确边界。
- 实现上可以先落一部分模块，但不能让首版原型野生生长。

### 2.2 上下文按需装载

- Aida 不应默认携带完整项目上下文工作。
- 每个模块只能装载完成当前任务所需的最小上下文。
- `PCB`、规则、`Backlog`、`SIS`、运行记录都应按需提炼后再进入上下文。

### 2.3 模块可独立演进

- 会前准备、会议输入处理、分流沉淀、回写通知、会议主持、DoD 评估、Pulse Execution Sync、日志留痕、审查支持等能力应允许独立增强。
- 后续新增 Agent 或 Skill 时，不应要求重写整个 Aida。

### 2.4 流程能力与价值决策分离

- Aida 可以强流程、强沉淀、强治理。
- 但 `PO` 的价值取舍、优先级拍板、风险接受和资源投入决策仍应保留给人类。

## 3. 分层设计总览

当前建议把 Aida 拆为以下五层：

1. `治理约束层`（L1）
2. `流程编排层`（L2）
3. `工作模块层`（L3）
4. `协议与资产层`（L4）
5. `审计与评估层`（L5）

这五层不是五个独立程序，而是五种职责分层。

### 3.1 治理约束层

作用：

- 为 Aida 提供不可越过的规则边界。
- 定义什么能做、什么不能做、什么必须阻断。

主要输入：

- `AidaPulse会议治理总规则`
- `Aida职责边界总规则`
- `AS-1`、`AS-2`
- 后续 `G5` 流程守门与阻断机制

输出：

- 当前阶段允许动作
- 阻断条件判断
- 提醒 / 异议 / 阻断结论

### 3.2 流程编排层

作用：

- 判断当前处于哪个阶段。
- 决定应该调用哪个工作模块。
- 控制模块的执行顺序与回退路径。

关键特点：

- 它是 Aida 的"流程大脑"
- 但它不直接做复杂内容生产，而是调度模块完成工作

### 3.3 工作模块层

作用：

- 承担单一、可明确描述的工作能力。
- 每个模块只做一类事情，避免职责混杂。

当前建议的工作模块：

- 会前检查模块
- 会前辅助包模块
- 会议表单接收模块
- 信息缺口追问模块
- 会议结论分流模块
- 会后回写模块
- 通知模块
- 未决议题更新模块
- 资产装载模块
- 会议主持模块（Planning / Review / Retrospective，其中 Retrospective 为可选：Aida 建议 + PO 认可才开）
- DoD 评估模块（读取 DoD 定义，逐项对照实际产出做通过 / 不通过判断）
- Pulse Execution Sync 模块（事件驱动的异步状态同步，取代每日站会）

### 3.4 协议与资产层

作用：

- 为各模块提供标准输入输出协议。
- 管理 `Backlog / SIS / PCB / 会议表单 / 未决议题池 / 运行记录` 等资产的读取与写入接口。

关键特点：

- 工作模块不直接"理解整个项目"，而是通过这一层取得被提炼后的结构化输入。
- `SIS` 是 AI 侧主视图。
- `Backlog` 是人类侧主视图。

### 3.5 审计与评估层

作用：

- 审计日志留痕：记录 Aida 的关键判断、关键动作和关键产物。
- 审查支持：为后续评审与优化提供审计证据。

当前阶段定位：

- 优先做审计日志，不优先做细粒度调试日志。
- 优先回答"是否做了正确的事、是否得到正确结果"。
- DoD 评估已移至 L3 工作模块层（与白皮书 7.1 对齐），本层只保留审计日志留痕与审查支持。

## 4. 模块清单（首版建议）

> 说明：以下是认知设计上的细拆。`Aida v0.1.0` 首版不要求全部做完，但后续实现不得偏离这份设计总图。

#### M1 阶段识别与流程守门模块

对应：

- `AS-1`

职责：

#### M2 会前检查模块

- `AS-2`

- 判断是否具备开会条件

#### M3 会前辅助包模块

- 生成会前摘要、输入清单、议程确认提示

### 4.2 会议输入处理模块

对应：

- `AS-3`

职责：

- 校验表单完整性

#### M5 一轮追问模块

对应：

- `AS-3`

职责：

- 识别信息缺口
- 对关键缺项发起一轮澄清追问

### 4.3 资产沉淀模块

#### M6 会议结论分流模块

对应：

- `AS-4`

职责：

- 将结论分流到：
  - `SIS`
  - `Backlog`
  - 未决议题池
  - 过程记录

#### M7 会后回写模块

对应：

- `AS-5`

职责：

- 更新 `Backlog`
- 更新 `SIS`
- 更新纪要
- 更新未决议题池

#### M8 通知模块

- `AS-5`

- 异步通知 `PO`
- 视情况提醒 `PC / PT`
- 在短 Sprint 场景中通知流程变化（短 Sprint 的"短"体现在时间维度上，不限制任务数量）

### 4.4 上下文支持模块

#### M9 资产装载模块

对应：

- `AS-6`

职责：

- 按需读取和压缩：
  - `PCB`
  - 当前规则
  - 相关 `Backlog`
  - 相关 `SIS`

### 4.5 审计与评估模块

#### M10 审计日志模块

对应：

- `AS-11`

职责：

- 记录关键判断
- 记录关键动作
- 记录关键产物去向

#### M11 审查支持模块

对应：

- `AS-12`

职责：

- 提供后续评审所需的日志、产物、比对信息

#### M12 DoD 评估模块

> 所属层级：L3 工作模块层（与白皮书 7.1 对齐）

对应：

- 白皮书 3.3.2 Layer 4 能力

职责：

- 读取 Sprint 启动文档中的 DoD 定义
- 逐项对照实际产出做通过 / 不通过 / 部分通过判断
- 对未通过项给出处理建议
- 形成对照表供 Review 使用

#### M13 Pulse Execution Sync 模块

> 所属层级：L3 工作模块层（与白皮书 7.1 对齐）

对应：

- 白皮书 4.3 Pulse Execution Sync

职责：

- 在事件发生时即时广播并 @ 相关人员（取代每日站会）
- 触发条件包括：任务完成通知、资源告警、风险通告、卡点需要人工清障、SIS 执行状态更新
- 生成 Pulse Execution Sync 事件日志，作为审计和 Retrospective 的决策辅助依据

### 4.6 会议主持模块

#### M14 会议主持模块

> 所属层级：L3 工作模块层（与白皮书 7.1 对齐）

对应：

- 白皮书 3.3.2 Layer 3 能力
- 白皮书 4.2 / 4.4 / 4.5

职责：

- 主持 Planning 会议：开场 -> 候选收集 -> 三级收敛 -> 顺序确认 -> 产出启动文档 -> 回写
- 主持 Review 会议：开场 -> 回顾承诺 -> 汇报交付 -> 审查式清单 -> PO 反馈 -> Backlog 处理 -> 决定下一步
- 主持 Retrospective 会议（可选：Aida 建议 + PO 认可才开）：开场 -> 汇报数据 -> 团队回顾 -> 识别瓶颈 -> 形成改进项 -> 判断回流 -> 产出纪要

## 5. 上下文边界设计

上下文边界是 `AS-9` 的核心，不只是"模块叫什么"。

### 5.1 全局上下文

以下内容不应在每次调用时完整注入，而应通过资产装载模块按需提炼：

- 白皮书
- `PCB`
- 全量 `Backlog`
- 全量 `SIS`
- 全部会议记录
- 全部运行日志

### 5.2 模块级上下文

每个模块只应获得完成当前任务所需的最小信息。

示例：

- 会前检查模块只需要：
  - 会议类型
  - 当前阶段
  - 本次会议输入清单
  - 必要规则

- 一轮追问模块只需要：
  - 当前表单
  - 缺口字段
  - 追问规则

- 结论分流模块只需要：
  - 会议结论
  - 分流规则
  - 当前相关 `Backlog / SIS` 引用

### 5.3 必须共享的最小上下文

以下内容应视为跨模块共享的最小公共上下文：

- 当前流程阶段
- 当前会议类型
- 当前相关 `Backlog ID`
- 当前相关 `SIS ID`
- 当前规则版本

### 5.4 必须隔离的上下文

以下内容不应默认跨模块共享：

- 全量推理过程
- 与本任务无关的历史会议详情
- 与本任务无关的项目背景细节
- 不属于当前模块职责范围的内部判断草稿

这样做的目标是：

- 降低 token 消耗
- 提升聚焦度
- 降低错误传播

## 6. 编排关系设计

当前建议的主编排链路如下：

1. `流程编排层` 识别当前阶段
2. 调用 `治理约束层` 判断是否允许继续
3. 调用对应工作模块
4. 由 `协议与资产层` 提供最小上下文和标准输入
5. 工作模块产出结果
6. 由 `审计与评估层` 记录关键证据
7. 若需要，回到流程编排层决定下一步

### 6.1 会议后主链路

这是 `Aida v0.1.0` 首版最关键的工作主链：

1. 会议表单接收
2. 一轮追问
3. 会议结论分流
4. 会后回写
5. 异步通知
6. 审计留痕

### 6.2 短 Sprint 执行期间的并行链路

在短 Sprint 场景中，Pulse Execution Sync 模块作为事件驱动的异步状态同步机制，贯穿整个执行过程，与上述主链路并行运行：

- 任务执行完成时广播通知
- 遇到卡点时通知人工清障
- 生成事件日志供审计和 Retrospective 使用

### 6.3 为什么 `AS-9` 和 `AS-10` 要串行

- `AS-9` 先输出总图
- `AS-10` 再按总图落原型

原因：

- 避免 `Aida v0.1.0` 先长成一个无法拆分的整体
- 避免首版为了能跑，把长期边界做坏

## 7. Aida v0.1.0 首版实现建议

认知设计上，应承认所有模块存在。  
实现上，`Aida v0.1.0` 首版建议优先落以下模块：

- `M1` 阶段识别与流程守门
- `M4` 会议表单接收
- `M5` 一轮追问
- `M6` 会议结论分流
- `M7` 会后回写
- `M8` 通知
- `M10` 审计日志

暂时可以先不完整落地的模块：

- `M2 / M3` 更完整的会前能力增强
- `M9` 更复杂的资产装载和压缩
- `M11` 更完整的审查支持机制
- `M12` DoD 评估模块（短 Sprint 场景下优先级提升）
- `M13` Pulse Execution Sync 模块（短 Sprint 场景下优先级提升）
- `M14` 会议主持模块（Planning / Review / Retrospective 标准会议主持能力）

---

## 8. 首版原型的上岗标准

`Aida v0.1.0` 不要求一开始就成为正式产品，但至少要达到：

1. 能接收会议表单输入
2. 能完成一轮追问
3. 能把结论分流到正确资产
4. 能完成会后回写与通知
5. 能留下关键工作审计日志

达到这个状态，就可视为：

- 原型机开始上岗
- 能脱离当前长对话的强依赖
- 能用真实运行数据反哺后续优化

---

## 9. 当前不做什么

为避免 `AS-9` 范围失控，当前不做以下事情：

- 不直接输出完整代码实现
- 不在 `AS-9` 中顺手确定全部目录实现细节
- 不追求一次把所有模块落地
- 不把完整产品化形态提前塞入首版设计

---

## 10. 与后续条目的关系

- `AS-10` 应严格建立在 `AS-9` 设计输出之上
- `AS-11` 使用 `AS-9` 中的模块边界定义关键日志点
- `AS-12` 使用 `AS-9` 中的主链路定义审查重点
- `AS-6` 将补强 `M9` 资产装载模块
- `D4 / D5 / D6 / D8` 将补强协议与资产层
- `M12` DoD 评估模块将与 Review 会议（`M14`）协作，提供逐项对照结论
- `M13` Pulse Execution Sync 模块将为 `AS-11` 审计日志和 Retrospective 提供事件输入
- `M14` 会议主持模块将串联 Planning / Review / Retrospective 三种核心会议流程

---

## 11. 当前阶段结论

`AS-9` 的核心结论不是"做一个最小骨架"，而是：

- 先定义一张长期稳定的架构总图
- 明确模块层次
- 明确上下文边界
- 明确编排关系
- 再在这张总图上安全地制作 `Aida v0.1.0`

这样后续迭代才不会因为首版求快，而陷入痛苦的结构返工。
