# PCB 标准模板（项目背景蓝图）

> 版本：v0.1.0
> 资产归类：产品资产 -> 标准模板
> 作用：定义 AidaPulse 框架中 PCB（Project Context Blueprint，项目背景蓝图）的标准结构。PCB 是每个项目唯一的一份项目级纲领，是 Aida 在具体项目中判断"做什么、不做什么、边界在哪"的定制配置依据。
> 设计原则：Aida 拿到一份新项目的初始需求后，套用本模板即可生成该项目的完整 PCB 文档。

---

## 0. 模板定位

| 层 | 文件 | 职责 |
|----|------|------|
| 框架级纲领 | 白皮书 | 定义通用规则、通用流程、通用架构 |
| 项目级纲领 | PCB（本模板） | 定义单个项目的定制配置、项目特定规则 |
| 冲突处理 | — | 项目级纲领优先于框架级纲领（需经 PO 确认） |

PCB 是**项目特定**的建设资产，每个项目一份；本模板是**可复用**的产品资产，跨项目通用。

### 初始需求收集方式（不规定死）

生成 PCB 依赖"初始需求"（新项目的背景、目标、边界）：

- 优先使用初始需求表单（若已存在）
- 没有表单时，**不设阻断**，在可沟通时由 Aida 向 PO 追问补齐
- 追问以"能填满本模板各章节所需的最小信息"为界，不做过度调研

### PCB 定稿硬约束（项目启动前提）

PCB 是项目启动的纲领，**必须先定稿、后开工**，这是硬性前提：

- **时限**：最后一个 Grooming 会议结束前，或第一次 Planning 会议开始前，必须与 PO 将 PCB 定稿
- **责任**：Aida 必须主动确保该约束成立——在时限临近时主动发起定稿确认，不得拖延、不得跳过
- **后果**：PCB 未定稿则项目无法开始，禁止进入 Planning 及后续任何执行环节
- **定稿含义**：PO 对 PCB 各章节明确确认（允许遗留"待补充"项，但须 PO 知情并同意后续补齐，不得有阻塞性悬而未决项）
- **完整性校验（仅首次）**：**第一次**进入 Planning 前，Aida 按本模板各章节核对 PCB 完整度；**校验不通过时，Aida 必须提醒 PO 不得开启 Planning，并由 PO 决定新开一次 Grooming 会议来继续定稿 PCB**，直到校验通过后才能进入 Planning。此校验只在第一次进入 Planning 时执行，后续周期不再重复

| 字段 | 必填 | 说明 |

| `title` | 是 | 固定语义"项目背景蓝图"，可加项目名 |

| `date` | 是 | 创建/更新日期 |
| `upgrade_note` | 是 | 版本升级说明 |

## 2. 正文标准章节

### 第 1 章：产品灵魂 (Vision & Soul)

> 写什么：这个项目为什么存在、服务谁、与框架的对应关系。

- **1.1 核心愿景**：一句话说明项目要解决什么问题、达成什么结果
- **1.2 目标用户**：服务谁（团队、角色、组织）
- **1.3 与白皮书的映射关系**：框架概念（AI 编排中枢、脉冲小队、SIS、记忆系统、工作流图、异步广播）在本项目中的具体实例是什么

### 第 2 章：系统架构图谱 (Architecture Map)

> 写什么：本项目的架构配置、数据流、记忆载体、工作流。

- **2.1 本项目特定配置**：核心组件、关键工件、交互角色、执行模式
- **2.2 当前数据流**：从 PO 意图输入到 Aida 报告预警的完整数据流转
- **2.3 文件记忆管理系统**：L1/L2/L2.5/L3 四层记忆在本项目的落地
- **2.4 全流程工作流图**：项目遵循的阶段流转 + 关键设计决策（阻断/回流/可选环节等）

### 第 3 章：项目规则 (Project Rules)

> 写什么：本项目的定制规则与 Aida 的运行断言。

- **3.1 项目特定规则**：执行模式、文件管理、资产依赖、版本管理、阻断策略等
- **3.2 Aida 运行断言**：Aida 在本项目中的运行前提（如"总能根据记忆知道阶段"）
- **3.3 补充原则**：记忆一致性、单向依赖、分层职责边界等

### 第 4 章：术语表 (Glossary)

> 写什么：本项目特定或需补充的术语定义（通用术语引用白皮书即可，不重复）。

### 第 5 章：当前项目状态

> 写什么：项目所处阶段、已完成里程碑、当前核心资产目录。

- **5.1 项目阶段**：当前 Sprint / 阶段 / 原型版本
- **5.2 已完成里程碑**：历次 Sprint 及成果
- **5.3 当前核心资产**：目录结构及各目录用途

### 第 6 章：进化记录 (Evolution Log)

> 写什么：按时间顺序记录项目的关键演进节点（版本升级、里程碑、重大决策）。

### 第 7 章：反面教材 (Anti-Patterns)

> 写什么：本项目必须避免的行为和误区（通用反面教材引用白皮书，此处仅列项目特定的）。

## 4. 生成流程

```
1. 获取初始需求（表单优先，无表单则在可沟通时追问 PO）
2. 套用本模板生成 PCB 草稿
3. 逐章节填写，无法填写的标记"待补充"
4. PO 确认 PCB 草稿（或追问补齐后确认）
5. 【门禁（仅首次）】最后一次 Grooming 会议结束前 / **第一次** Planning 开始前，Aida 必须与 PO 完成 PCB 定稿确认；Aida 先按各章节校验 PCB 完整性——校验不通过时，提醒 PO 不得开启 Planning，由 PO 决定新开 Grooming 继续定稿；校验通过后 Aida 记录定稿结论，方可进入 Planning 及后续环节。此门禁仅在项目第一次进入 Planning 时执行，后续周期不再重复
6. PCB 落盘到 {新项目}/project/pcb/
```

## 5. 当前不做什么

- 不把 PCB 模板与具体项目实例绑定（模板是通用结构，实例是项目特定内容）
- 不硬性规定初始需求表单（有最好，没有不卡，追问 PO）
- 不要求 PCB 一次填满（允许"待补充"，在可沟通时补齐）
