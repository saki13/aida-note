# SKILL 标准模板

> 版本：v0.1.0
> 资产归类：产品资产 -> 标准模板
> 作用：定义 AidaPulse 框架中 SKILL 文档的标准结构。SKILL 是对 Aida 能力的延伸或规范，Aida 本身维护整个项目工作流的顺利推进，SKILL 为其提供具体能力的执行规则。
> 设计原则：新建 SKILL 时套用本模板，保证结构统一、装载时机明确、与记忆系统关系清晰。现有 SKILL 在下次大改时顺便对齐即可，不做强制回溯。

---

## 0. 模板定位

| 层 | 文件 | 职责 |
|----|------|------|
| Agent 执行载体 | `Aida_v0.1.0_SKILL` | 维护整个项目工作流的顺利推进，是节奏驱动者 |
| SKILL 能力规则 | `AS-x_xxx` | 对 Aida 某项具体能力的延伸或规范 |
| 标准模板 | 本文件 | 定义 SKILL 文档的统一结构，供后续新建 SKILL 参考 |

SKILL 是**产品资产**，跨项目可复用（带出去做新项目时只读）；本模板同样是产品资产，定义 SKILL 的标准结构。

---

## 1. Frontmatter 标准字段

```markdown
# {SKILL名称}

> 版本：v0.1.0
> 资产归类：产品资产 -> SKILL 能力规则
> 对应 Backlog：`{Backlog ID}` {Backlog 名称}
> 作用：{一句话说明本 SKILL 定义什么能力、解决什么问题}
> 上级文档：[AidaPulse 白皮书 v0.1.0](../whitepaper/AidaPulse白皮书_待确认.md)
```

### 必填字段（5 项）

| 字段 | 说明 |
|------|------|
| `版本` | 当前版本号 |
| `资产归类` | 固定为 `产品资产 -> SKILL 能力规则`（Agent 执行载体为 `产品资产 -> Agent 执行载体`） |
| `对应 Backlog` | 追溯到具体 Backlog Story，确保双向链接 |
| `作用` | 一句话说明本 SKILL 定义什么能力 |
| `上级文档` | 通常为白皮书，可加具体章节 |

### 选填字段（4 项，按需添加）

| 字段 | 说明 | 使用场景 |
|------|------|---------|
| `状态` | 如 `prototype-active` / `stable` | Agent 执行载体必填，AS 系列按需 |
| `依赖文档` | 本 SKILL 依赖的其他文档 | 有前置依赖时填 |
| `关联规则` | 与本 SKILL 有协作关系的其他规则 | 有跨规则协作时填 |
| `演进` | 本规则的演进方向说明 | 预留后续升级方向时填 |

### 字段顺序

版本 -> 资产归类 -> 状态(选) -> 对应 Backlog -> 作用 -> 上级文档 -> 依赖文档(选) -> 关联规则(选) -> 演进(选)

## 2. 正文标准章节

### 第 1 章：目标

> 写什么：本 SKILL 要达成什么能力，不是什么。

统一用"目标"作为章节名（不用设计目标/能力目标/规范目标等变体）。包含：
- 本 SKILL 的核心目标（1-3 句话）
- 该能力至少要做到什么（列举要点）
- 该能力**不是**什么（明确边界，防止过度设计）

### 第 2 章：边界

> 写什么：管什么、不管什么。

- **管什么**：本 SKILL 覆盖的职责范围
- **不管什么**：明确不归本 SKILL 管的事项（交给谁）

### 第 3 ~ N 章：实现细节

> 写什么：本 SKILL 的具体执行规则。

各 SKILL 自由定义，常见模式：
- 触发时机（什么时候调用）
- 执行流程（怎么做）
- 输入输出契约
- 状态流转
- 与其他 SKILL 的协作关系

### 第 N+1 章：与记忆系统的关系

> 写什么：本 SKILL 在记忆系统中的位置、装载时机、变更追溯。

**这是本模板的核心约束**，每个 SKILL 必须回答：

| 维度 | 说明 |
|------|------|
| **记忆层引用** | 本 SKILL 在哪层记忆被引用 |
| **装载时机** | 什么时候被装载到 Aida 的上下文中 |
| **变更追溯** | 本 SKILL 的变更如何被记录 |

具体：
- **L1 manifest**：是否登记在 `manifest.md` 的按序装载清单中？（启动恢复时装载）
- **L2.5 context_cache**：是否有对应缓存条目？（按需装载时供给摘要）
- **L3 decisions**：变更记录到 `decisions.md`

装载时机分类：
| 时机 | 说明 | 典型场景 |
|------|------|---------|
| 启动恢复 | L1 manifest 装载清单中的常驻项 | 治理规则、核心能力规则 |
| 阶段切换 | 进入特定阶段时按需装载 | 会议相关 AS（AS-2/3/4/5） |
| 任务按需 | 执行特定任务时按需装载 | AS-SIS、AS-Panel |
| 审查触发 | 审查阶段触发装载 | AS-11、AS-12 |

### 第 N+2 章：当前不做什么

> 写什么：本 SKILL 当前版本明确不做的事情。

显式列出，防止 scope creep。与第 2 章"不管什么"的区别：第 2 章是职责边界（永远不管），本章是当前版本限制（后续可能做）。

## 4. 当前不做什么

- 不强制回溯现有 13 个 AS 文件的结构（现有文件稳定运行，下次大改时顺便对齐）
- 不把 Agent 执行载体（Aida SKILL）强制套用本模板（其结构差异大是正常的，Aida 是工作流推进者，SKILL 是能力延伸）
- 不限制实现细节章节的数量和命名（各 SKILL 自由定义第 3~N 章）
- 不一次性把模板做到完美（先有粗框架，后续迭代优化）
