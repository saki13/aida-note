# 阶段流程重审表（7.1d）

> 资产归类：产品资产 -> 流程定义（工作流图第 3 节的统一重审版）
> 版本：v0.1.2（已确认，2026-08-18 回写工作流图第 3 节）
> 对应 Backlog：`7.1` 约束执行防错机制（7.1d 全量重审各阶段）
> 状态：PO 已确认（2026-08-18）

## 说明

- 本表覆盖 10 阶段 + 新增「项目交付」，逐阶段固定四段：**进入条件 → 执行 → 输出 → 收口检查**。
- **通用收口检查**：4 同步点核对（①decisions ②Backlog ③data.json ④state+manifest），各阶段在此之上叠加阶段特定检查，缺一视为未收口。
- 阶段顺序：项目准备 → Grooming → Planning → Sprint In Progress → Sprint Completed → Review → Retrospective（可选）→ Planning Input Ready →（循环回 Planning 或进入项目交付）；短 Sprint 脉冲为可选分支（= Aida 获 PO 权限后走 3+4+5+6+7+8），脉冲执行同步贯穿 Sprint In Progress。

| 1 | 项目准备 | PO 提供项目意图、初始资料 | 接收意图，辅助 PO 形成初始 PCB 和 Backlog 雏形 | 初始 PCB、初始 Backlog | 4 同步点 + PCB/Backlog 初步成型 |
| 2 | Backlog Grooming | PCB 含项目目标/角色/术语表；Backlog 存在 | 读 PCB/Backlog 建理解 → 辅助整理子任务 → 评估反馈 → 记录未决事项 | 更新后 Backlog、未决议题记录、**更新后 manifest（PCB 成型后同步记忆）** | 4 同步点 + Backlog 有 5–10 排序候选项、未决议题已记录、**manifest 已同步 PCB/Backlog 状态** |
| 3 | Planning | Backlog + **未决议题** + 上一轮反思纪要（如有）+ 会议规则/纪要模板 | 开场范围确认（**先咨询未决议题进度，短 Sprint 无视**）→ 拉候选 → 三级收敛 → 顺序确认 → 产出启动文档 → 回写资产 | Sprint 启动收口文档、更新后 Backlog、更新后 manifest/state | 4 同步点 + 正式输入已锁定、候补/暂缓已区分、启动文档已产出、无不可执行项误选 |
| 4 | Sprint In Progress | 启动文档 + Backlog + manifest + state + SKILL | **长 Sprint**：Aida 与 PO 共同决定每个 Backlog 项的负责人/agent，并行执行并追踪各任务进度；agent 自动获取任务，人类负责人通过输入与交付物把 Backlog 项推进到「待检查」状态，由 Aida 做 DoD 检查通过后关闭。<br/>**短 Sprint**：Aida 自行将任务交给 agent，按依赖关系并行/串行执行并追踪进度。<br/>**每个任务完结后 Aida 立即做 DoD 检查（不等阶段 5）** → 产生异步广播事件 | 交付物、更新后 state、审计轨迹、事件日志 | 4 同步点 + 所有任务有明确状态（待检查/已关闭）、交付物已产出 |
| 5 | Sprint Completed | 启动文档（对照 DoD）+ state + 交付物 | 检查交付完整性 → 读 DoD → **对全部任务做一次总体 DoD 复查**（每个任务已单独做过 DoD，此处是总体再查一次）→ DoD 对照表 → 未通过项建议 → 发起 Review | DoD 对照表、Review 发起通知 | 4 同步点 + 总体 DoD 复查完成 |
| 6 | Review | 启动文档 + DoD 对照表 + 交付物 + 审计轨迹 + 纪要模板 | 开场范围确认 → 回顾承诺 → 汇报 → 审查式清单 → PO 反馈认可 → Backlog 处理 → 决定下一阶段 | Review 报告、更新后 Backlog | 4 同步点 + Review 报告已产出、PO 已给出判断、**检查 Backlog 池是否空（空则询问 PO 是否交付项目）** |
| 7 | Retrospective（可选） | Aida 建议 + PO 认可 | 汇报过程数据 → 团队回顾 → 识别瓶颈 → 形成改进项 → 判断回流方向 → 产出纪要 | 反思纪要、改进项清单、回流/新增 Backlog 项 | 4 同步点 + 反思纪要已产出 |
| 8 | Planning Input Ready | Review 报告 + 反思纪要（可选）+ Backlog | 提取候选项 → 整理候选清单 → 检查 Backlog 剩余 → 燃尽则转项目交付 / 有剩余则进 Planning | Planning 输入候选清单 | 4 同步点 + 候选清单已产出、Backlog 剩余状态明确 |
| 9 | 短 Sprint 脉冲（可选分支） | PO 授权（有限次，AS-8）+ Backlog 明确 + 高内聚需求 + AI 可自主评估 DoD | **短 Sprint = Aida 获得 PO 权限后，自主走 3+4+5+6+7+8 完整 Sprint 流程**；授权次数/边界受 AS-8 约束，事件流同步 PO | 短 Sprint 启动决策 + 3~8 各阶段产出 | 4 同步点 + 授权次数未超限、事件流已同步 data.json.events[] |
| 10 | 脉冲执行同步（贯穿 Sprint） | 任务完成/资源告警/风险通告/卡点/ SIS 状态更新 | 事件发生时即时广播并 @ 相关人员 | Pulse Execution Sync 事件日志 | 4 同步点 + 事件已记录进 data.json.events[] |
| 11 | 项目交付（新增） | Review 阶段检查 Backlog 池已空，且 PO 决定进入交付 | Aida 生成项目报告 → 询问 PO 意见 | 项目报告、项目产品、evolution_log 等项目资产 | 4 同步点 + PO 意见已给出（同意→交付齐全；否决→进入新 Planning） |
