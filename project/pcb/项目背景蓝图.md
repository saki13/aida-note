## 1. 产品灵魂 (Vision & Soul)

### 1.1 核心愿景

做一个**轻便、功能全面**的桌面文本编辑器：在单一窗口内优雅地查看与编辑多语法文本（html / sql / js / json / markdown），以**所见即所得**方式编写并实时渲染 mermaid 图表，具备格式化（美化）与文件对比能力，并通过可配置的第三方 API 接入有限的 AI 能力（润色 / 问答 / mermaid 修复）。不追求 IDE 级复杂度。

### 1.2 目标用户

- 首要用户：PO 本人（自用刚需，必须好用）。
- 定位：非产品化 / 分发导向，但技术选型保留跨平台可移植性，便于将来分发。

### 1.3 与白皮书的映射关系

| 框架概念 | 项目实例 |
|---------|---------|
| AI 编排中枢 | Aida v0.1.0 作为本项目的节奏驱动者 / 项目经理 |
| 脉冲小队 | PO（用户，兼任 PC/PT）+ Aida |
| 结构化指令集（SIS） | 由 Backlog 转化的可执行任务指令集 |
| 记忆系统 | `memory/` 四件套（manifest / state / decisions / context_cache） |
| 流程守门 | G5、AS-1 阶段识别与流程守门 |
| 工作流图 | 标准 11 阶段流程（项目准备 → … → 项目交付） |
| 异步事件广播 | Pulse Execution Sync 事件日志 |

## 2. 系统架构图谱 (Architecture Map)

### 2.1 本项目特定配置

**技术栈（产品实现层）**

| 层 | 选型 | 说明 |
|----|------|------|
| 桌面壳 | Tauri 2 | Rust 壳 + 系统 WebView2，轻便（安装包小、内存低、启动快） |
| 前端框架 | Vue 3 + TypeScript + Vite | 状态密集型工具 UI（标签页 / 侧栏 / 设置 / AI 面板）；UI 组件库 = Naive UI |
| 编辑器内核 | CodeMirror 6 | 模块化、极轻；多语法高亮 + 同屏所见即所得装饰层 |
| 图表渲染 | mermaid.js | 代码块原位实时渲染 |
| 格式化 | Prettier | 覆盖 html / js / json / markdown（SQL 格式化暂不支持，做减法） |
| 文件对比 | 轻量 diff 库 + 双栏 | 替代 Monaco 内置 diff |

**关键工件（建设资产）**：`project/pcb/`、`project/backlog/`、`project/sis/`、`project/sprint/`、`project/panel/workflow/data.json`、`project/change_log.md`、`project/evolution_log.md`。

**交互角色**：PO（用户，兼任 PC/PT）、Aida（节奏驱动者 / 项目经理）。

**执行模式**：待 Planning 阶段确定（长 Sprint 或短 Sprint）。

### 2.2 当前数据流

> 本 PCB 描述的是"开发本项目"的 AidaPulse 数据流，非编辑器产品内部数据流。

```
PO 意图输入
  → Aida 收集需求 / 生成 PCB
  → 建立 Product_Backlog（主事实源）
  → Grooming（硬阻断：PCB 必须定稿）
  → Planning（三级收敛 + 产出 Sprint 启动文档）
  → Sprint 执行（Backlog → SIS 转化 → 执行 → DoD）
  → Review → Retrospective（可选）
  → 项目交付
  → Pulse Execution Sync 异步事件广播 + 审计日志
```

### 2.3 文件记忆管理系统

| 层 | 文件 | 落地 |
|----|------|------|
| L1 | `memory/manifest.md` | 新会话统一恢复入口 + 装载清单 |
| L2 | `memory/state.md` | 当前阶段 / 任务 / 阻塞快照 |
| L2.5 | `memory/context_cache.md` | 关键文档精简摘要 |
| L3 | `memory/decisions.md` | 跨会话关键决策日志 |

### 2.4 全流程工作流图

标准 11 阶段：项目准备 → Backlog Grooming → Planning → Sprint In Progress → Sprint Completed → Review → Retrospective（可选）→ Planning Input Ready → 短 Sprint 脉冲 → 脉冲执行同步 → 项目交付。

**关键设计决策**：
- 仅 `Backlog Grooming` 设**硬阻断**（PCB 必须定稿）。
- 阶段切换必须显式申请并等 PO 批准（程序正义）。
- Review 不可跳过；Retrospective 可选（Aida 建议 + PO 认可）。

## 3. 项目规则 (Project Rules)

### 3.1 项目特定规则

- **执行模式**：待 Planning 阶段确定（长 / 短 Sprint 二选一，短 Sprint 需 PO 授权）。
- **文件管理**：遵循三层目录约定（product / project / memory），单向依赖。
- **资产依赖**：`project/` 依赖 `product/`，反向禁止。
- **版本管理**：PCB / Backlog / SIS / Sprint 文档均带版本号与日期。
- **阻断策略**：PCB 定稿为项目启动硬前置；Backlog Grooming 设硬阻断。

### 3.2 Aida 运行断言

- Aida 总能通过记忆系统恢复当前阶段，不依赖长对话上下文。
- Aida 下任何结论前先答守门两问：①该需求/表述是否成立 ②该结论是否需要 PO 批准。
- Aida 不得代替 PO 做价值优先级拍板。

### 3.3 补充原则

- **记忆一致性**：state / manifest / data.json 的 stage 字段同步更新，缺一视为未收口。
- **单向依赖**：product 不依赖 project，memory 不承载产品规则。
- **分层职责边界**：产品资产（可回流）进 product，项目特定进 project。

## 4. 术语表 (Glossary)

| 术语 | 定义 |
| :--- | :--- |
| 同屏所见即所得 | 编辑区即渲染区：标题/加粗/列表直接显示效果，光标所在段落露出源码（Typora 式） |
| 软换行（Word Wrap） | 显示时按屏宽折行，保存时不写入换行符，默认开启、可开关 |
| mermaid 实时渲染 | mermaid 代码块在编辑区原位渲染为图表，随源码实时更新 |
| 文件对比（diff） | 双栏并排展示差异，高亮增删行；源 = 两个独立文件 + 当前文件 vs 剪贴板（历史版本对比后续） |
| 格式化（美化） | 对 html / json / js / markdown 按规范自动排版（SQL 格式化暂不支持） |
| AI 接入 | 前端直连兼容 OpenAI 协议的第三方 API（可配 baseURL + key + model） |
| P0 / P1 / P2 | 优先级：P0=MVP 必做；P1=下一批；P2=明确不做 |

## 7. 反面教材 (Anti-Patterns)

- 不做 IDE 级功能：不运行脚本 / 程序，不监听文件夹，不做工程管理。
- 不做跨文件全局搜索（避免滑向 IDE）。
- 不做多窗口 / 分屏。
- 不做文件树 / 文件夹侧栏。
- 不为"有限 AI 接入"引入 Rust 侧密钥桥接（过度设计）。
- 不因"功能全面"牺牲"轻便"这一首要定位。
