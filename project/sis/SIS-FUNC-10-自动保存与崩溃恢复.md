# SIS：自动保存 / 崩溃恢复草稿

## 1. 任务目标

实现 aida-note 的崩溃恢复能力：对未保存（脏）的标签，停止输入后防抖自动写草稿到临时目录；应用异常退出后，下次启动检测到草稿并弹窗提示恢复或丢弃；正常退出、恢复完成、过期残留均清理，不留碎片。草稿仅用于恢复，不替代手动保存。

- 必须完成：
  - 自动草稿：对未保存（脏）标签，停止输入后防抖触发写草稿到临时目录
  - 恢复提示：下次启动检测到草稿 → 弹窗提示「恢复 / 丢弃」
  - 覆盖范围：仅脏标签（已保存且无修改的标签不写草稿）
  - 清理策略：正常退出清理 + 恢复后清理 + 过期残留清理（不留碎片）
- 建议完成：
  - 恢复列表展示（多个标签草稿时逐个恢复）
  - 草稿写入临时目录，文件名含时间戳/标签标识
- 当前不做：
  - 不做全量自动保存到原文件（不替代用户显式 Ctrl+S）
  - 不做版本历史（属 FUNC-6 历史版本对比，已往后放）

## 2. 人类意图

PO 原始表达（2026-08-20 逐项问答确认，FUNC-10 全部"照推荐"）：

- 防抖触发：停止输入后防抖写草稿（避免频繁写盘）
- 弹窗提示：下次启动检测到草稿 → 弹窗提示恢复/丢弃
- 仅脏标签：只对未保存（脏）标签做草稿
- 完整清理：正常退出 + 恢复后 + 过期残留均清理，不留碎片

## 3. 输入 / 输出契约

- 输入：
  - FUNC-1（tabsStore 脏标记、标签内容）
  - ARCH-2（临时目录约定）
  - Tauri fs 插件（写临时目录）
- 输出：
  - 草稿自动保存服务（draftService：防抖监听脏标签 → 写临时目录）
  - 启动恢复检测与弹窗（恢复/丢弃）
  - 清理逻辑（退出清理 / 恢复后清理 / 过期残留清理）
- 输出位置：`d:\lucia\workspace\aida-note\app\`（src/services、src/components、src/stores）

## 4. 边界与约束

- 可以改：防抖阈值、临时目录具体路径、草稿文件命名格式、过期判定时长
- 不能改：
  - 仅脏标签写草稿（不写已保存无修改标签）
  - 弹窗提示恢复/丢弃（不静默自动恢复）
  - 完整清理：退出 + 恢复后 + 过期残留（不留碎片）
  - 草稿不替代手动保存（不自动写回原文件）
- 必须遵守：
  - 草稿存临时目录，不污染用户文件目录
  - 与 FUNC-1 脏标记逻辑衔接（保存成功 → 清理对应草稿）
  - 崩溃残留的草稿在下次启动时能被识别与清理

## 5. 验收标准

- [ ] 脏标签停止输入后防抖自动写草稿到临时目录
- [ ] 已保存且无修改的标签不产生草稿
- [ ] 模拟崩溃后重启，弹窗提示恢复/丢弃
- [ ] 选择「恢复」后，草稿内容恢复到对应标签并置脏标记
- [ ] 选择「丢弃」后，对应草稿被删除
- [ ] 正常退出时草稿被清理，临时目录无残留
- [ ] 恢复完成后草稿被清理
- [ ] 过期残留草稿被清理（不留碎片）
- [ ] 草稿不会自动写回原文件（需用户显式保存）
- [ ] `npm run dev` 可手动验证，`npm run build` 通过
