01

项目准备阶段

正常 ＋

收集资料、组建团队

输入

PO 的项目意图、初始资料

Aida 动作

接收项目意图，辅助 PO 形成初始 PCB 和 Backlog 雏形

输出

初始 PCB（project/pcb/项目背景蓝图_待确认.md）、初始 Backlog（project/backlog/Product_Backlog_待确认.md）

阻断条件

无（起始阶段）

→ 有初始资料
02

Backlog Grooming

正常 ＋

待办事项整理

→缺失基础资产
阻断

Backlog Grooming (Blocked)

缺少 PCB / Backlog / 未决议题（G5 硬阻断）

→按模板生成最小 PCB / Backlog + 问卷
↺ 返回 Backlog Grooming

输入

  • PCB：project/pcb/项目背景蓝图_待确认.md
  • Backlog：project/backlog/Product_Backlog_待确认.md
  • 白皮书：product/whitepaper/AidaPulse白皮书_待确认.md
  • 会议治理规则：product/rules/会议治理总规则_待确认.md

Aida 动作

  1. 读取 PCB 和 Backlog，建立全局理解
  2. 辅助 PO 整理子任务，以结构化文档/指令集输出
  3. 给出评估反馈，PO 负责澄清模糊点
  4. 记录未决事项

输出

更新后的 Backlog、未决议题记录

阻断条件

  • 无初始 PCB
  • 无初始 Backlog
  • 无未决议题记录

补救：按 PCB 模板生成最小化 PCB；按项目要素生成初始调研 Backlog + 问卷，问卷收敛后进入下一个 Grooming 任务

→ PCB + Backlog + 未决议题齐备
03

Planning

正常 ＋

脉冲计划会议

→三级收敛 + 产出启动文档
完成

Planning Completed

已产出启动收口文档

→无任务池

◆ Backlog 是否还有剩余项？

无任务池时检查是否项目完成

→有剩余
↺ 回到 Planning
→无剩余，项目完成

项目交付

直接进入收尾（跳到终点）

输入

  • Backlog：project/backlog/Product_Backlog_待确认.md
  • 上一轮 Retrospective 纪要（如有）
  • 会议治理规则、会议纪要模板

Aida 动作

  1. 开场与范围确认
  2. 从 Backlog、反思结论、候补项池拉取候选，按优先级呈现
  3. 三级收敛：范围确认 → DoD 与前置依赖检查 → 锁定正式输入/候补/暂缓
  4. 执行顺序确认（Aida 建议，PO 确认）
  5. 产出 Sprint 启动收口文档
  6. 回写资产（Backlog、manifest、状态快照）

输出

Sprint 启动收口文档（project/sprint/Sprint启动收口_xxx.md）、更新后的 Backlog、更新后的 manifest 和 state

阻断条件

无可用任务池（PO 确认没有新任务 → 项目已完成，走项目收尾）

→ 常规执行
04

Sprint In Progress

＋

执行 Sprint 任务 + 异步事件广播

→来自 Planning Completed：PO授权 + 准入满足

◆ 短 Sprint 准入检查

PO授权 + Backlog明确 + 高内聚需求 + AI可自主评估

→是 / 否，转常规 Sprint
→ 均进入 Sprint In Progress

输入

  • Sprint 启动收口文档（project/sprint/Sprint启动收口_xxx.md）
  • Backlog、manifest (L1)、state (L2)
  • Aida SKILL 执行载体（product/agents/aida/Aida_v0.1.0_SKILL_待确认.md）

Aida 动作

  1. 从 manifest 找到 in_progress 任务继续，或启动下一个 pending 项
  2. 推进任务执行 → 产生异步广播事件
  3. 完成一个任务后先回核主事实源，再启动下一个 → 广播
  4. 调用 AI 本身或其他专项 Agent 自动执行 SIS → 广播
  5. 卡点需人工清障时 → 广播
  6. 资源告警或风险通告时 → 广播

输出

任务交付物、更新后的 state.md、审计轨迹（project/traces/audit_trace_xxx.md）、异步广播事件日志（project/traces/events_xxx.md）

阻断条件

无。Sprint 执行阶段不设阻断，问题通过异步广播事件通知，由 PO 决定是否介入

→ 所有任务完成
05

Sprint Completed

正常 ＋

所有任务已有明确状态

输入

  • Sprint 启动收口文档（对照 DoD 定义）
  • state.md (L2 状态快照)
  • 所有任务的交付物

Aida 动作

  1. 检查交付完整性
  2. 读取启动文档中的 DoD 定义
  3. 逐项对照实际产出做通过/不通过判断
  4. 形成 DoD 对照表
  5. 对未通过项给出处理建议
  6. 自动发起 Review

输出

DoD 对照表、Review 发起通知

阻断条件

无交付成果可展示（回退到 Sprint In Progress 继续执行）

→ 发起评审
06

Review

正常 ＋

评审会议（含 3 种结果）

→通过

Review Passed

通过评审

→检查是否需要反思
→通过但有观察项

Review Passed With Observation

通过但有观察项

→检查是否需要反思
→未通过

Review Failed

未通过，需纠偏

→纠偏后重新执行
↺ 回到 Sprint In Progress

输入

  • Sprint 启动收口文档（对照承诺）、DoD 对照表
  • 所有交付物、审计轨迹（project/traces/audit_trace_xxx.md）
  • 会议纪要模板

Aida 动作

  1. 开场与范围确认
  2. 回顾 Sprint 原始承诺
  3. Aida 汇报完成情况
  4. 审查式清单：目标 / 交付物 / Aida 表现 / 一致性 / 风险与未通过项
  5. PO 反馈与认可判断（必须由 PO 给出正式判断）
  6. Backlog 与状态处理
  7. 决定下一阶段

输出

Review 报告（含 DoD 对照表和审查结论）、更新后的 Backlog（关闭完成项，未通过项回流）

阻断条件

无主动阻断。未通过项回流到下次 Planning 或反思会；Review 结论必须产出，未产出则补写

→ 检查是否需要反思
07

Retrospective

可选 ＋

反思与进化会议（Aida 建议 + PO 认可后触发）

◆ Aida 是否建议开反思会？

输入来自 Review Passed / With Observation

→不需要
→ Planning Input Ready（下一阶段）
→Aida 建议 + PO 认可
可选

Retrospective（反思会议）

反思与进化会议

→产出纪要

Retrospective Completed

已产出反思纪要

→进入下一轮准备
→ Planning Input Ready

触发条件

Aida 觉得 Sprint 中有做的不好的、需要讨论的问题（未完成、效果不理想等），通知 PO 建议开启反思会，PO 认可后才走此流程

输入

  • Review 报告、审计轨迹
  • Sprint 中的异步广播事件日志（决策辅助依据）
  • project/reports/ 下的审查报告、会议纪要模板

Aida 动作

  1. 开场与范围确认
  2. 汇报过程数据（风险、阻塞、未通过项、关键事件、异步广播事件统计）
  3. 团队回顾（PO 反馈：做得好的 / 做得不好的）
  4. 识别瓶颈（流程 / 协作 / 工具 / 质量）
  5. 形成改进项（方向、责任人、优先级）
  6. 判断回流方向（回流规则 / 新增 Backlog / 仅记录）
  7. 产出反思纪要

输出

反思纪要（project/meetings/Sprint反思_xxx.md）、改进项清单、回流规则或新增 Backlog 项

阻断条件

无主动阻断。未形成有效结论 → 把问题作为待完善项加入 Backlog 或在原 Backlog 上修改

→ 进入下一轮准备（或不需要反思）
08

Planning Input Ready

正常 ＋

Aida 自省，准备下一轮

→Backlog 有剩余
↺ 回到 Planning

输入

  • Review 报告
  • 反思纪要（可选，如有）
  • Backlog（检查剩余项）：project/backlog/Product_Backlog_待确认.md

Aida 动作

  1. 从反思结论中提取候选项（如有反思纪要）
  2. 整理为 Planning 输入候选清单
  3. 检查 Backlog 是否还有剩余项
  4. Backlog 燃尽 → 项目交付；还有剩余 → 自动进入下一轮 Planning

输出

Planning 输入候选清单

阻断条件

无。只要有 Backlog 就可以进入 Planning

→ Backlog 燃尽
09

项目交付

完成 ＋

Backlog 燃尽，客户满意

输入

Backlog 已燃尽（无剩余项）

Aida 动作

项目收尾，交付软件产品，确认客户满意

输出

可交付的软件产品

阻断条件

无
